## Qué listas están vigentes (noviembre de 2026)

| Lista | Edición vigente | Aplica a |
|---|---|---|
| **OWASP Top 10** (aplicaciones web) | **2025**: presentada en noviembre de 2025, versión final en enero de 2026. Primera actualización desde 2021 | Backend Spring Boot |
| **OWASP API Security Top 10** | **2023**: sigue siendo la última; no existe una edición "API 2025" | API REST `/api/v1` |
| **OWASP Mobile Top 10** | **2024**: primera gran revisión desde 2016 | App Android |
| OWASP Top 10 for LLM Applications | 2026 | No aplica: Abarrato no usa modelos de lenguaje en la app |

Cambios del Top 10:2025 frente al de 2021:

- Hay dos categorías nuevas: **A03 Fallas en la cadena de suministro de software** y **A10 Mal manejo de condiciones excepcionales**.
- SSRF dejó de ser categoría propia y se integró en A01.
- **Configuración incorrecta** subió al puesto 2.

## 1. OWASP Top 10:2025 · Backend

| ID | Categoría | Estado en Abarrato | Evidencia o acción |
|---|---|---|---|
| A01 | Control de acceso roto (incluye SSRF) | ✅ | La API pública es de solo lectura. La única ruta que escribe (`/actualizar`) exige un token. Contra SSRF, el servidor solo visita los dominios fijos de las 8 tiendas y valida el formato de cada pasillo (`ExploradorCatalogos.Ruta`) |
| A02 | Configuración de seguridad incorrecta | ✅ | Cabeceras (`CabecerasSeguridad`), sin trazas en los errores, sin CORS, contenedor sin root (`Dockerfile`), HTTPS forzado |
| A03 | Fallas en la cadena de suministro | 🟡 | `jsoup` con versión fija y CI. **Pendiente**: Spring Boot 3.5 ya no recibe parches gratuitos (junio de 2026) → migrar a 4.x; activar Dependabot o `dependency-check` |
| A04 | Fallas criptográficas | ✅ | TLS en la app, en Cloud Run y en Neon (`sslmode=require`). No se guardan contraseñas de usuarios |
| A05 | Inyección | ✅ | SQL siempre parametrizado; comodines de `LIKE` escapados; probado en `CajaGrisTest` |
| A06 | Diseño inseguro | ✅ | Amenazas analizadas en D11: límite de peticiones, tamaño máximo de cuerpo, sin datos personales en el servidor |
| A07 | Fallas de autenticación | ✅ | Sin cuentas de usuario por diseño (D2). El token de la tarea es largo y aleatorio, se compara en tiempo constante y debe rotarse si se expone |
| A08 | Fallas de integridad de software o datos | 🟡 | Flyway verifica la suma de control de cada migración; `CHECK` en la base (V10). Falta firmar el APK de release y fijar la imagen base del Dockerfile por su *digest* |
| A09 | Fallas de registro y alertas | 🟡 | Logs en Cloud Run; IP validada antes de registrarla (CWE-117, `pareceIp`). **Pendiente**: crear una alerta en Cloud Monitoring si la tarea diaria falla o si aumentan los 5xx o 429 |
| A10 | Mal manejo de condiciones excepcionales | ✅ | Manejador central; ante fallas se rechaza (token vacío → 404); si una tienda cae, se usa la última captura; tiempos máximos de espera |

| ID | Riesgo | Estado | Evidencia o acción |
|---|---|---|---|
| M1 | Uso inadecuado de credenciales | ✅ | El APK no contiene claves; solo la URL pública de la API |
| M2 | Cadena de suministro | ✅ | Pocas dependencias; Leaflet incluido localmente, con su licencia |
| M3 | Autenticación o autorización insegura | ✅ N/A | Sin cuentas |

## 4. Hallazgos corregidos en esta revisión

1. **Inyección en logs (A09, CWE-117)**: la IP de `X-Forwarded-For` podía traer saltos de línea. Ahora se valida con `pareceIp` (probado en `CajaBlancaTest`).
2. **Contenedor como root (A02)**: el `Dockerfile` ahora usa el usuario `abarrato`.
3. **Integridad en la base (A08)**: restricciones `CHECK` en `V10__restricciones_integridad.sql`.
4. **Copias de seguridad de la app (M9)**: `allowBackup="false"`.
5. **Privilegios de base de datos (A01, ISO 27002 8.2)**: perfiles en `db/roles.sql`.
6. **Precisión de la ubicación compartida con terceros (M6)**: las coordenadas se redondean a 3 decimales y viajan por POST.
